# Voice confirmation playback fix

## Observed failure

The approved September 17 signup test repeatedly asked to save contact details despite clear assent. The user explicitly authorized inspection of that call. The transcript and worker diagnostics confirmed three `playback_not_acknowledged` validation failures before the action API or database claim. The contact proposal existed, but playback and confirmation evidence stayed empty; no contact action or signup send executed. All delegated model requests returned output. Closing the call superseded its unconfirmed action as designed.

The existing playback gate waited for the output queue to become completely empty. Live audio also contains continuous silence, which can keep that queue nonempty after the permission question has finished. Existing logs establish the missing acknowledgment but do not retrospectively measure that call's buffer contents. The regression harness reproduces the continuous-silence failure directly.

## Narrow correction

- Inspect remaining audio one paced frame at a time, including partial tails, to determine whether audible output is still waiting.
- Require fresh audible output received and actually forwarded after the pending question was armed.
- Allow the phone playback mark once that audible output drains, even while silent frames remain queued. Continue requiring the actual phone acknowledgment.
- Preserve complete spoken readback checks, caller evidence, corrections, stale-action checks and database claim rules. No phrase-based consent shortcut is added.
- Add safe marker-queued diagnostics, without speech, contact details or provider credentials.

No migration, app route, tone, prompt, billing, pilot eligibility or commercial setting changes are needed. The deployment target is the voice worker only. Existing dashboard release and restored Leads remain intact.
